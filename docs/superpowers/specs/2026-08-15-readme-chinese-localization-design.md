# README 中文化设计

## 目标

将仓库主 `README.md` 从中英文混排统一为中文，使中文用户能够连续阅读，同时保留开发、测试、打包和运行说明的准确性。

## 已选方案

主 README 全中文，命令、路径、环境变量、文件名、协议名、产品名和必要技术术语保留英文。当前不新增 `README.en.md`，避免维护两份可能逐渐失真的说明。

曾考虑以下方案：

1. 仅把现有中文“使用方法”翻译成英文。改动最小，但不符合项目当前面向中文评审与使用者的主要场景。
2. 主 README 全中文。阅读连续、维护成本低，是本次采用的方案。
3. 中英文分文件。覆盖面最广，但会增加同步维护成本，当前没有明确的英文文档需求。

## 内容与结构

- 保留现有标题层级、章节顺序、代码块、命令和配置示例。
- 翻译项目简介、能力、业务智能体、开发设置、模型配置、工作流、最终验证、打包和运行时数据等英文说明。
- 保留已经使用中文编写的“使用方法”，仅在需要时统一术语和语气。
- 不增删产品能力，不改变首发版本边界，不加入自动发布 Shopify 或 eBay 的表述。

## 术语规则

- `Agent`、`Skill`、`Tool`、`Artifact`、`Product/SKU`、`Product Graph`、`Human Approval` 保留英文项目术语，首次出现时可辅以中文说明。
- `Shopify`、`eBay US`、`Electron`、`FastAPI`、`Vite`、`SQLite` 等专有名称不翻译。
- `Canonical Product/SKU` 统一表达为“规范 Product/SKU”，避免同一概念出现多种译法。
- 路径、环境变量、命令、端口和文件格式保持原样。

## 验证

- README 的章节标题和说明段落不再出现无意的英文正文；代码块、专有名词和技术标识除外。
- 现有命令、路径、环境变量、端口、测试范围和首发版本边界与改写前一致。
- `git diff --check` 通过。
- Markdown 围栏、标题层级、列表编号和链接保持有效。

## 非目标

- 不新增英文版 README。
- 不修改应用代码、测试、配置或产品行为。
- 不重新设计 README 信息架构，不增加徽章、截图或营销内容。
